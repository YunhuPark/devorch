# 사용자 인터뷰 가이드 (3~5명, 사람당 30분)

목적: "AI 코딩 작업에 승인선과 예산 상한을 거는 도구"가 **실제로 필요한 사람이 있는지**, 있다면 **누가 왜 쓸지** 알아내는 것.
설득하러 가는 자리가 아닙니다. 사람들이 이미 어떻게 하고 있는지를 듣는 자리입니다.

## 누구를 만나나
- AI 코딩 도구(Claude Code, Cursor, Copilot 등)를 **이미 업무에 쓰는** 개발자·팀 리드. 쓰지 않는 사람은 답이 추측이 됩니다.
- 가능하면 서로 다른 입장 섞기: 혼자 쓰는 개발자 / 팀 리드 / 보안·비용을 챙기는 사람(있다면).
- 친구라서 좋게 말해 줄 사람은 1명 이하.

## 순서

### 1. 현재 상태 듣기 (10분, 도구 소개 전에)
소개를 먼저 하면 답이 그쪽으로 끌려갑니다. 아래를 먼저 묻습니다.
1. AI 에이전트가 코드를 고치게 할 때, 반영되기 전에 **지금 무엇을 하시나요?** (diff를 읽는다 / 테스트만 돌린다 / 그냥 merge한다)
2. 마지막으로 AI가 만든 **잘못된 코드가 그대로 반영된 적**이 있나요? 언제, 어떻게 알았고, 무슨 일이 생겼나요?
3. AI 사용 **비용**을 누가 신경 쓰나요? 월 얼마쯤이고, 예상보다 크게 나온 적이 있나요?
4. 팀에서 "이 작업은 AI에게 맡기지 말자"는 규칙이 있나요? 있다면 어떻게 지키나요?

기록할 것: 구체적 사건(날짜·금액·영향)과 현재 쓰는 해결책. 의견("있으면 좋겠다")보다 **이미 쓴 시간·돈·도구**가 신호입니다.

### 2. 한 문장 소개 (2분)
> AI 코딩 작업에 예산 상한과 승인선을 거는 도구입니다. 위험한 작업은 사람이 직접 승인해야만 별도 브랜치에 커밋되고, 위험하지 않은 작업은 검증 비용을 아낍니다.

바로 묻기: **"이게 무슨 문제를 푸는 도구라고 이해하셨나요?"** — 본인 말로 다시 설명하게 합니다. 어긋나면 문장이 문제입니다.

### 3. 직접 보여주기 (10분)
`docs/IDE_CHECK.md` 의 흐름(분석 → 에이전트가 수정 → 승인 필요에서 멈춤 → 사람이 터미널에서 승인 → 브랜치에 커밋 → `devorch finish` → merge)을 **보여주기만** 합니다. 직접 해 보게 하면 설치 문제로 시간이 갑니다.
볼 것: 어디서 표정이 바뀌는지, 어디서 질문이 나오는지, 어디서 지루해하는지.

### 4. 반응 확인 (8분)
1. 지금 쓰는 방식과 비교해 **무엇이 더 낫고 무엇이 더 번거롭나요?**
2. 승인 단계가 **귀찮아서 끄게 될 것 같은** 순간이 있나요? 언제요?
3. 팀에서 쓴다면 **누가 승인**하나요? 그 사람이 터미널을 열어야 하는 게 괜찮은가요?
4. 이걸 쓰려면 **무엇이 있어야** 하나요? (CI 연동, 대시보드, Slack 알림, 다른 에디터 지원…)
5. 돈을 낸다면 **무엇에** 내시겠어요? 얼마가 적당한가요? (추측 가격이라도 기록. 단 "쓰겠다"는 말은 신호로 치지 않습니다.)

### 5. 마무리 (2분)
- "비슷한 문제가 있는 분을 한 분 소개해 주실 수 있나요?" — 소개해 주겠다는 것이 가장 강한 긍정 신호입니다.
- 2주 뒤 직접 써 볼 의향이 있는지, 있다면 날짜를 잡습니다.

## 하지 말 것
- "성능이 좋다", "버그를 잡아준다"고 말하지 않기. 우리 평가에서 AI 리뷰어는 실제 버그 12개 중 최대 약 40%를 찾았고, 그 수치는 일반화할 수 없습니다(HANDOFF 참고). 내세울 수 있는 것은 **승인 없이는 반영되지 않는 통제**와 **측정 가능한 비용 상한**입니다.
- 샌드박스 없이는 "신뢰할 수 없는 에이전트를 막는다"고 말하지 않기. 기본 설정(sandbox none)에서는 테스트 코드가 키를 읽어 스스로 승인할 수 있음을 재현했습니다. 막으려면 Docker 샌드박스가 필요합니다. 질문이 나오면 그대로 답합니다.
- 기능 아이디어를 그 자리에서 약속하지 않기.

## 기록 양식 (인터뷰마다 복사)
```
날짜 / 역할·팀 규모 / 쓰는 AI 도구:
현재 반영 전 절차:
실제 사고 사례 (날짜·영향·금액):
비용 인식 (월 지출, 놀란 적):
한 문장 소개를 본인 말로 요약한 것:
가장 크게 반응한 장면 / 지루해한 장면:
승인 단계를 끌 것 같은 순간:
쓰기 위한 조건:
지불 의사 (말한 금액, 신호 강도 상/중/하):
소개받은 사람 / 2주 뒤 재시도 날짜:
```

## 끝난 뒤 판단 기준 (미리 정해 둠 — 결과를 보고 바꾸지 않기)
- **계속**: 5명 중 3명 이상이 (a) 구체적 사고나 비용 초과 사례를 말했고 (b) 지금 그것을 막는 마땅한 수단이 없다고 했다.
- **방향 전환 검토**: 사고·비용 사례가 거의 없고 "있으면 좋겠다" 수준의 말뿐이면, 통제보다 다른 가치(예: 비용 가시화만)로 좁히는 것을 검토.
- 3~5명은 **방향을 가늠하는 용도**일 뿐 통계가 아닙니다.
