# 약해진 테스트 감지 — 실제 이력 평가 (사전 등록: 결과를 보기 전에 작성)

작성 시점: 2026-10-22, **데이터를 보기 전**. 이 문서의 기준은 결과를 본 뒤 바꾸지 않는다(바꾸면 변경 이력과 이유를 아래에 남기고 이전 결과와 직접 비교하지 않는다).

## 무엇을 묻나
`src/devorch/core/analyzer/test_weakening.py`(v1, 규칙 고정)가 **실제 공개 저장소의 실제 커밋**에서
1. 테스트를 약하게 만든 커밋을 얼마나 잡는가(재현율의 대리 측정),
2. 걸린 커밋 중 정말 약화였던 비율은 얼마인가(정밀도).
기존 측정은 합성 사례(재현율)와 표본 5건(정밀도)뿐이라 이를 실제 데이터로 대체한다.

## 데이터
- 공개 Python 저장소 6곳을 새로 복제: `psf/black`, `pallets/click`, `marshmallow-code/marshmallow`, `Delgan/loguru`, `python-poetry/poetry`, `nicolargo/glances`.
- 복제한 코드는 **읽기만** 한다(실행하지 않음). 대상은 각 저장소의 머지가 아닌 커밋 중 **테스트 경로를 건드린 커밋**, 최근 순으로 저장소당 최대 1,500개.
- 감지기는 DevOrch 에서 diff(`git diff <c>~1 <c>`)를 입력으로 돌린다. 규칙은 v1 그대로.

## 라벨 정의 (W = 약화)
**W(약화):** 기존 테스트의 검증이 **삭제·건너뛰기·무력화**됐고, 같은 커밋 안에 **동등한 검증이 다른 형태로 남아 있지 않고**, 커밋이 **테스트 대상 기능 자체를 지우는 것도 아닌** 경우. 불안정(flaky)해서 무조건 skip 한 것도 W(검증이 사라지므로).
**N(정당):** 대상 기능 삭제에 따른 테스트 삭제, 같은 검증의 형태 변경(`pytest.raises`·parametrize 등), 파일 간 이동, 플랫폼·버전 조건부 skip(검증이 해당 환경에서 계속됨), 이름 변경, 의미 있는 새 테스트 추가, 기타.
애매하면 **U(불명)** 로 따로 세고 계산에서 제외하되 개수를 보고한다.
**라벨러는 나(Claude, 개발에 쓴 모델과 같은 계열)다 — 편향 가능.** 모든 라벨과 한 줄 이유를 `docs/test_weakening_labels.csv` 로 남겨 누구나 다시 판정할 수 있게 한다.

## 표본
- **재현율의 대리 집합 K:** 커밋 제목이 아래 **고정 정규식**에 맞는 커밋(제목이 테스트를 지우거나 건너뛰었다고 스스로 말하는 커밋). 후보가 많으면 저장소·시기와 무관하게 **무작위 60개**(시드 20261022).
  `\b(skip|skipped|skipping|xfail|disable|disabled|remove|removed|delete|deleted|drop|dropped|ignore|ignored|comment out)\b.{0,40}\b(test|tests|testcase|testcases)\b` 또는 `\b(test|tests)\b.{0,40}\b(skip|skipped|xfail|disable|disabled|flaky|removed|deleted)\b` (대소문자 무시)
  K 를 라벨링해 W 로 확인된 것 중 감지기가 잡은 비율을 **재현율(대리)** 로 보고한다. 한계: 제목이 그렇게 말하지 않는 약화는 못 본다(재현율은 이 집합 안에서의 값).
- **정밀도 집합 F:** 같은 데이터에서 감지기가 걸린 커밋 중 **무작위 60개**(시드 20261022). 걸린 수가 60 이하면 전부.
- 두 집합의 라벨링 결과는 95% Wilson 구간과 함께 보고한다. 표본이 작으면 작다고 쓴다.

## 하지 않는 것
- 라벨을 본 뒤 감지기 규칙·임계값을 고치지 않는다. 개선안은 v2 후보로만 기록하고, **새 데이터(다른 저장소/기간)** 에서 따로 잰다.
- 합성 데이터는 쓰지 않는다. (단위 테스트의 합성 diff 는 코드 정확성 확인용이고 이 평가의 근거가 아니다.)

## 결과
(2026-10-22, 사전 등록한 방법 그대로. 모든 라벨과 이유: `docs/test_weakening_labels.csv`. 채굴·열람·집계 스크립트: `tools/eval/test_weakening/`.)

### 데이터
6개 저장소에서 테스트 경로를 건드린 커밋 **4,840개**(black 807, click 578, marshmallow 932, loguru 478, poetry 1,500, glances 545). 감지기가 건 커밋 **481개 = 9.9%**, 그중 HIGH(두 종류 이상)는 43개 = 0.9%. K 집합(제목 정규식 일치) 55개 전부, F 집합 무작위 60개(시드 20261022)를 라벨링했다.

### 재현율(대리) — K 집합
| | 개수 |
|---|---|
| 라벨 W(약화) | 8 |
| 그중 감지기가 잡음 | **5 → 62.5% (95% 구간 31~86%)** |
| 불명(U) | 2 |
놓친 W 3개: ① CI 매트릭스에서 Windows+3.13 제외(테스트 *파일* 밖 — 감지 범위 밖), ② `self.skipTest(`(unittest 의 무조건 skip — 패턴에 없음), ③ 단언을 주석 처리(`# self.assertEqual(` 의 `assert` 를 *추가된 단언*으로 세서 순감소가 상쇄됨).
한계: 제목이 그렇게 말하는 커밋 안에서의 값이다. 제목이 말하지 않는 약화는 이 집합에 없다.

### 정밀도 — F 집합 60개
| 판정 | 개수 |
|---|---|
| W(실제 약화) | **1** |
| N(정당) | 55 |
| U(불명) | 4 |
**정밀도 1/56 = 1.8% (95% 구간 0.3~9.4%)**, 불명 4개를 모두 약화로 쳐도 상한 5/60 = 8.3% (3.6~18.1%).
정당(N) 55개의 유형(제 라벨 이유 기준 분류): 리팩터·재구성·이동·형태 변경 24, 조건부 skip/xfail 14, 테스트 대상 기능·동작 삭제 11, 새 테스트·새 기능 5, 기타 1.

### 해석
- 감지기는 **약화의 약 6할을 잡지만, 걸린 것의 대부분(약 92~98%)이 정당한 변경**이다. 이 데이터(사람이 쓴 커밋)에서 "걸렸다 = 약화"라고 말할 수 없다.
- **이 평가는 사람의 커밋이다. AI 에이전트가 실패하는 테스트를 지우는 경우의 기저율은 알 수 없다**(에이전트 이력 데이터가 없음). 에이전트에서 기저율이 높다면 정밀도는 더 좋을 수 있고, 이 데이터는 그것을 말해 주지 못한다.
- 라벨러는 나(개발에 쓴 모델과 같은 계열)이므로 편향 가능성이 있고, 라벨 정의(조건부 skip 은 N, 기능 삭제에 따른 테스트 삭제는 N)가 결과를 크게 좌우한다 — 그래서 모든 라벨을 CSV 로 공개한다.

### 이 결과로 한 결정과 하지 않은 결정
- **감지 규칙은 바꾸지 않았다**(사전 등록 유지). 이 평가는 v1 규칙에 대한 것이다.
- **기본 동작을 바꿨다:** 기본값을 "위험도를 올림(enforce)"에서 **"조언만 함(advise)"** 으로 바꿨다(`policy.yaml` 의 `test_weakening: advise | enforce | off`). 이유: 걸린 커밋의 대부분이 정당한데 기본으로 리뷰어·승인을 붙이면 대부분이 소음이다. advise 는 리뷰 응답의 `notes` 와 감사 로그에만 "테스트 약화 의심"을 남기고 비용·승인 부담이 없다. enforce 는 에이전트가 테스트를 지워서 통과시키는 것을 특히 경계하는 소유자가 직접 켠다.
- **v2 후보(적용 안 함 — 새 저장소·기간에서 따로 재야 함):** `self.skipTest(`·`pytest.raises`·`assertRaises` 인식, 주석 줄 제외, 조건이 붙은 skip(`skipif`, 조건 안의 `skip`)과 무조건 skip 구분, 같은 diff 에서 소스 삭제(기능 삭제)를 동반한 테스트 삭제 제외, 파일 간 이동 추적, CI 설정(워크플로 매트릭스) 변경 인식. 위 오탐 유형별 개수가 우선순위의 근거다.
