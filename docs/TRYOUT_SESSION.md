## 무엇을 확인하나 — 그리고 확인하지 않는 것
- **확인하는 것:** 처음 쓰는 사람이 README만 보고 설치 → 첫 실행(`devorch quickstart --mock`) → (Claude Code가 있으면) MCP 연결 → 첫 요청까지 **혼자서** 갈 수 있는가, 어디서 막히는가, 핵심 개념을 이해하는가.
- **확인하지 않는 것:** 수요(이 도구를 쓰고 싶은가), 탐지 성능, 비용 절감. 이 세션은 **사용성 확인**이다. "쓰고 싶다"는 말은 기록만 하고 신호로 치지 않는다.
- 참가자를 평가하는 시험이 **아니다.** 막히면 그건 문서나 도구의 문제로 기록한다.

## 진행자 규칙 (측정의 일부)
1. 화면을 공유하거나 옆에서 **관찰만** 한다. 질문에는 바로 답하지 않고 "어떻게 하시겠어요?"라고 되묻는다.
2. **2분 이상 진전이 없을 때만** 힌트를 준다. 힌트를 줄 때마다 시각·단계·이유를 기록한다(힌트 횟수가 핵심 지표다).
3. 설치 중 기다리는 시간(`pip install`)은 정상이므로 막힌 것으로 치지 않되, 걸린 시간은 잰다.
4. 세션 뒤 이해 확인 3문항을 묻는다(아래). 정답을 알려 주기 전에 답을 먼저 받아 적는다.

## 참가자에게 줄 안내문 (그대로 복사해서 전달)

> 도구를 시험하는 것이지 당신을 시험하는 것이 아닙니다. 막히면 도구·문서의 잘못이니 편하게 말씀해 주세요. 15분 안에 어디까지 가는지만 봅니다. 비용도 키도 필요 없습니다.
>
> **A. 설치 (약 5분)** — 터미널에서 한 줄씩 실행하세요.
> ```
> git clone https://github.com/YunhuPark/devorch.git
> cd devorch
> python -m venv .venv
> ```
> 가상환경 켜기: Windows PowerShell은 `.\.venv\Scripts\Activate.ps1`, macOS/Linux는 `source .venv/bin/activate`
> ```
> pip install -e ".[dev,llm]"
> ```
>
> **B. 연습용 프로젝트 만들고 첫 실행 (약 3분)** — 한 줄씩 실행하세요(Windows 기본 PowerShell은 `&&` 를 지원하지 않습니다).
> ```
> mkdir demo
> cd demo
> git init -b main
> git -c user.name=demo -c user.email=demo@example.com commit --allow-empty -m init
> devorch quickstart --mock
> ```
> 화면 안내를 읽고 정책 승인 질문에 답해 보세요. 연습용 프로젝트라 "테스트 명령을 자동 감지하지 못함" 주의는 무시해도 됩니다. (`devorch` 명령이 안 되면 `python -m devorch quickstart --mock`)
>
> **C. (Claude Code가 있으면) 연결 (약 3분)** — 4번 항목에 나온 `claude mcp add ...` 명령을 실행하고, Claude Code에서 `/mcp` 로 `devorch`가 Connected인지 확인하세요.
>
> **D. (선택) 첫 요청 — 분석만 (약 4분)** — Claude Code에 이렇게 말해 보세요: `devorch 로 분석만 해줘. 파일은 고치지 말고 위험도와 필요한 단계만 알려줘: 결제 금액 합계를 구하는 add 함수에 음수 방지 검사를 추가`. 에이전트가 위험도(CRITICAL)와 "사람 승인이 필요하다"는 안내를 보여 주는지 확인하세요. 연습용 빈 프로젝트라 "영향 범위 0개"로 나오는 것은 정상입니다.

## 결과 보고 규칙
- **n이 1~3이라 비율을 쓰지 않는다.** "P1은 A에서 N분, 막힌 곳은 …"처럼 **일어난 일의 목록**으로만 보고한다.
- 막힌 곳은 고치고(문서·도구), 고친 뒤의 효과는 **다른 사람**으로 다시 재야 한다. 같은 사람에게 다시 해서 "개선됐다"고 쓰지 않는다.
- 이 세션으로 "사용하기 쉽다"고 일반화하지 않는다. 말할 수 있는 것은 "N명이 처음 시도했을 때 이 지점에서 막혔다"까지다.
